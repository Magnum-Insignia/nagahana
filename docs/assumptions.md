# NagaHana L: assumptions of the build (2026-10-02)

The owner asked for the full model "with your assumptions of wherever if you think are missing more
details", and for "a small doc, write down all those assumptions, with reasoning & justification,
along with any findings to cite from code runs or real world research". This is that document.

## How to read it

- **D-xx** is the owner's decision (`governance/decisions.py`). **AS-xx** is an engineering
  assumption standing in for a held decision or filling an unspecified detail. A held decision stays
  **held**: the assumption is the build's working choice, not the owner's decision.
- Every assumption is in the code registry (`governance/assumptions.py`). Code that relies on one
  calls `assume("AS-xx")`. `strict_mode(True)` makes every assumption raise, so an audit can run the
  code as if nothing were assumed.
- **The full reasoning, evidence and code-run findings** for AS-100 onward are in
  `docs/assumptions/<area>.md`, one section per ID. AS-01…AS-41 are written out in
  `governance/assumptions.py` itself.
- **How evidence is cited:** papers by authors, venue and arXiv ID; code runs as "code run: <test or
  script>, <number>". Where a fact was written from memory and not yet checked, the section says
  "(unverified)" or "(citation to verify)".

## Findings from the build that changed the design

These carry the evidence of code runs.

1. **A hidden clock in attention (fixed).**
   - The learned null key was scored with the time-rotated query, so outputs depended on time since
     an arbitrary origin, against D-49 and D-50.
   - Code run (TSTCT engineer): shifting a window's origin by 0.001–64 s changed outputs by up to
     7.5·10⁻³.
   - Fix: the null logit uses the un-rotated query (`null_q`), keeping the fused kernel. After the
     fix, the origin-shift difference is 1.4·10⁻⁶, and the strict-xfail tests that marked the bug
     now pass.
2. **Route weighting corrected (AS-251).** Imagined routes are sampled from the policy, so each draw
   weighs 1/N. The build-spec's weighting by the route's own probability counted the policy twice.
3. **Training reaches across time by carry, not by window size (D-51).**
   - Code run on the sample slice: 1,024 packet updates span only 2.6–23.8 s, and 4 of 5 windows
     hold no 60 s trigger.
   - Flow-state updates cut the baseline rate 4.8× but a scan only 1.2×, so carrying memory across
     windows is what reaches the triggers.
4. **Exactness of the memory design (tested):**
   - the two-stream loop makes training ≡ inference (incremental cache = parallel, 1e-5) and the
     Environment does not depend on R (bit-identical cache for R = 1 and 5);
   - windows with carry equal one dense window (9.5·10⁻⁷);
   - log-time cells are flood-invariant: a 10× flood leaves every older cell bit-identical;
   - mid-age recall: a state 1 day old is weighted the same as one 10 s old, where a FIFO of 512
     slots would have evicted it;
   - belief recursion across calls equals one call (1e-5).
